## A — Editorial Research

**核心概念：** 把首頁視為一篇研究隨筆的開場。左上大標題與右下介紹形成對角閱讀路徑，底部開放式索引接回作品。研究內容本身成為構圖材料，適合目前以論文和程式碼為核心的素材。

**首屏配置：** 頂部左姓名、右 GitHub；寬幅兩行標題；右下介紹及主要行動連結；最下方細線與三個作品名稱。主要入口和介紹形成一組，不與作品索引爭搶優先順序。

**設計系統：** 暖白 `#F5F2EB`、墨黑 `#202421`、深綠 `#355C4B`。標題以 Georgia／serif 為預定字體，正文用 `system-ui, sans-serif`；未假定有付費字型。生成稿只確認襯線與無襯線的視覺關係，不能證明實際字型。設計目標側邊留白約 6%，正文約 22–24 px；標題依可用寬度調整，而非要求像素照抄。

**作品延伸：** 使用開放式寬幅段落，左側短題目與研究問題，右側方法、可查閱成果和來源。第一案偏方法敘述，第二案可在有合適且可公開的真實素材後加入方法示意，第三案以工程流程與入口說明收束；不建立相同卡片牆。

**圖片使用：** 首屏不使用圖片。後續僅在能解釋方法時引入有來源且適合公開的圖；重繪流程須標示為方法示意，不能冒充實驗結果。

**手機調整：** 低於約 768 px 改單欄；取消對角錯位，依姓名、標題、介紹、主要入口、索引順序排列。標題預定 40–56 px、正文 18–20 px、側邊 20–24 px；允許自然換行，不為兩行限制縮字。三個作品名稱逐列排列，長名稱可換行。

**動態與複雜度：** 動態不必要，靜態即可成立。未來可採 CSS 連結底線及顏色回饋，無需 GSAP。桌面構圖與手機堆疊的實作複雜度低。

**優缺點：** 研究身份與個人品味最平衡，文字呼吸感強；但介紹偏右，需要清楚的手機重排，襯線比例亦須克制，避免被誤讀為文學作品集。

## B — Structured Index

**核心概念：** 把首頁變成清晰可查閱的作品索引。定位與作品在同一視野，讓合作對象快速找到研究和工程證據。

**首屏配置：** 姓名和 GitHub 分置頂部；左欄放標題、介紹與主要入口，右欄以三筆開放式索引列出作品。細直線區隔兩欄，水平細線區分作品，不包裝成卡片。

**設計系統：** 冷白 `#F4F6F7`、深灰 `#17212B`、深藍 `#244DA8`。標題及正文用 `system-ui, sans-serif`，索引序號才使用 `ui-monospace, monospace`。預定左欄約 43%、右欄約 51%，其餘留作欄距；標題約 62 px，中等字重。四行標題是窄欄構圖選擇，不視為必須縮字修正的錯誤。

**作品延伸：** 以作品目錄接完整敘述，案例採問題、方法、成果入口的短段落。文章順序維持研究、研究、工程；書目緊接案例，避免重複技術標籤。工程能力透過資料與檢索流程的說明呈現，不以假終端或假儀表板表現。

**圖片使用：** 索引不需縮圖；後續有實際說明價值時再加入真實方法圖或標明為示意的資料流程。

**手機調整：** 取消直線與兩欄，先定位後作品列表；保留作品分隔線，序號縮為輔助資訊。預定標題 40–52 px、正文 18–20 px、側邊 20–24 px，長作品名稱自然換行，不設橫向捲動。

**動態與複雜度：** 無需動畫。未來連結支援明確 focus 與 hover；整列是否可點擊須以真正目的地決定，避免產生重複連結。布局複雜度低。

**優缺點：** 三案中作品最容易立即掃讀，工程感最直接；但文字密度較高，左側大標題與右側作品會競爭注意力，個人情緒與編輯感較弱。

## C — Typographic Exhibition

**核心概念：** 以寬幅文字作為展覽式開場，讓研究與工程的雙重定位成為最鮮明的畫面。

**首屏配置：** 姓名與 GitHub 置頂；中央兩行大標題橫跨畫面；下方左介紹、右主要入口；底部以全寬作品文字帶收尾。沒有中間的左右主欄或卡片。

**設計系統：** 炭黑 `#17191B`、暖白 `#F2F0E9`、淡金 `#D7BE8A`。採 `system-ui, sans-serif`，標題半粗，預定約 96 px；側邊留白約 5–6%。不需要漸層、金屬材質、噪點或光暈。金色只用於入口，不代表獎項。

**作品延伸：** 以獨立寬幅章節一次講一案，先問題與方法，再接程式碼或書目入口。透過段落寬度、章節間距與字級變化形成節奏，不依靠連續動畫或重複巨大標題。

**圖片使用：** 首屏純文字；後續有來源的圖作為內容證據獨立呈現，不把研究圖當全屏裝飾背景。

**手機調整：** 標題預定 44–60 px 並自然換行；介紹與行動入口改為上下排列；底部文字帶改為三列索引。正文 18–20 px、側邊 20–24 px。不保留桌面兩行標題，也不以橫向捲動維持寬幅。

**動態與複雜度：** 靜態成立。未來可有約 150–200 ms 的 CSS 連結回饋；不需要進場遮罩或捲動綁定。字級、行長與小螢幕重排需多些調整，複雜度低至中。

**優缺點：** 首屏辨識度與視覺張力最強；標題容易壓過工程證據，長行介紹也較難閱讀。需要更謹慎地處理小型筆電的高度與橫向留白。

## 完成三案後的比較與推薦

| 比較面向 | A | B | C |
| --- | --- | --- | --- |
| 研究與工程定位 | 雙重定位清楚，研究氣質較強 | 雙重定位清楚，工程資訊優先 | 雙重定位最醒目，易先注意形式 |
| 首屏可讀性與留白 | 最舒展，介紹與入口分組明確 | 掃讀作品最快，主標與作品略競爭 | 對比鮮明，標題較逼近邊界 |
| 作品延伸能力 | 適合方法與成果的編輯式敘述 | 最適合直接查閱證據與目錄 | 適合逐案章節，須克制大字重複 |
| 個人辨識度 | 襯線與錯位構圖有辨識度 | 理性清楚但情緒較少 | 最具展覽式視覺張力 |
| 手機適應性（規格推估） | 需取消錯位，單欄順序清楚 | 兩欄改列表，最直接 | 大字與長行需較多調整 |

**推薦 A — Editorial Research。** 此判斷是在三張稿件生成並檢查後形成：A 讓研究與工程的共同主線完整可見，同時給介紹和作品入口足夠留白；其個性來自字體與排版，不需要額外媒體或效果。現有來源適合延伸為有證據的短案例，編輯式結構能承接這些內容。

B 是偏重快速找作品與程式碼時的有力選項；C 適合優先追求鮮明視覺開場。三案都保留，不以推薦代表使用者已選定，也不在本輪混合成第四案。

## 本輪邊界

僅完成內容與視覺探索，以及兩份指引的預設名稱同步。沒有實作首頁、增加框架、啟動伺服器、安裝依賴、提交、上傳或部署。後續須先選方向，再進入原型與瀏覽器驗證階段。
